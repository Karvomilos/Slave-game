# ПОДОПЫТНЫЙ 001

Telegram Mini App: HTML/CSS/JavaScript, FastAPI, aiogram 3 и PostgreSQL в Supabase. SQLite не используется.

## Что внутри

- `index.html`, `style.css`, `script.js` — социальный Хаб, тамагочи и мобильный интерфейс.

После загрузки открывается Хаб с режимами «Бутылочка» и «Комната нижнего». Ник, подтверждение 18+ и аватар задаются в Хабе; тип персонажа выбирается отдельно при входе в тамагочи. Кнопка «Уйти» сохраняет прогресс и возвращает в Хаб. Для Хаба используется отдельная генеративная эмбиент-тема. VIP и стартовый пак оплачиваются через ЮKassa; сервер выдает уровни VIP, монеты и предметы только после подтверждения платежа.
- `main.py` — API, WebSocket `/ws/room/{room_id}`, рефералы, платежи и Telegram-бот.
- `bottle_rooms.py` — комнаты до 10 игроков, вращение, выборы, рейтинг, подарки и чат.
- `db.py` — подключение к Supabase PostgreSQL и создание таблиц.
- `payments.py` — создание и серверная проверка платежей ЮKassa.
- `render.yaml` — Render Blueprint для Web Service.
- `token.txt` и `supabase_url.txt` — локальные секреты; в Git не добавляются.

Реферальная ссылка выдаёт новому игроку 10 клятв, а пригласившему — 25. Бонус начисляется один раз при первом входе приглашённого игрока. Самоприглашение не учитывается. В разделе «Друзья» отображается последняя игровая активность пригласившего и приглашённых.

После каждого полного часа отсутствия сервер применяет один офлайн-тик: здоровье уменьшается на 12 с учётом защиты тела, а настроение и достоинство изменяются по игровым правилам. Бот присылает результат и кнопку «Показатели». Проверка показателей и `/start` не считаются входом в игру; таймер обнуляют загрузка и автосохранение Mini App. При офлайн-смерти погибший персонаж удаляется из «комнаты власти».

«Крысиный король» показывает трёх крыс в комнате. Их крошки периодически повышают настроение, но не изменяют сытость.

## Локальный запуск

Требуется Python 3.11 или новее. Установите зависимости:

```powershell
py -m pip install -r requirements.txt
```

В файле `supabase_url.txt` замените `[YOUR-PASSWORD]` на пароль базы Supabase. Если пароль содержит специальные символы, закодируйте их для URL. Вместо файла можно задать переменную окружения:

```powershell
$env:DATABASE_URL="postgresql://postgres:PASSWORD@db.ogxbyxxydbomgoemaqan.supabase.co:5432/postgres"
$env:RUN_BOT="0"
$env:BOTTLE_ALLOW_DEMO="1"
py main.py
```

Откройте <http://127.0.0.1:8000> в двух окнах, подтвердите 18+ и войдите в «Бутылочку»: каждое окно получит отдельного demo-игрока и общую комнату `main`. `BOTTLE_ALLOW_DEMO` нужен только для локальной проверки без подписанного Telegram `initData`; на Render эту переменную не включайте. Для запуска бота уберите `RUN_BOT=0`, поместите токен в `token.txt` и задайте HTTPS-адрес игры через `GAME_URL`.

Таблицы создаются автоматически при старте. Существующие данные из старой локальной SQLite автоматически не переносятся.

## Как залить код на GitHub

1. Создайте пустой репозиторий на GitHub без README.
2. В папке проекта выполните, подставив адрес своего репозитория:

```powershell
git init
git add .
git commit -m "Deploy game"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

`token.txt`, `supabase_url.txt`, `game_url.txt`, `database.db` и `.tools/` перечислены в `.gitignore`. Проверьте перед push, что токен, пароль и ключи не попали в файлы проекта. Пример настроек без секретов находится в `.env.example`.

## Запуск на Render

1. В Render выберите **New + → Blueprint** и подключите GitHub-репозиторий.
2. Render найдёт `render.yaml` и предложит создать Web Service `slave-game-1`. Отдельная база Render не нужна.
3. В **Environment** задайте `DATABASE_URL` с реальным паролем Supabase и `BOT_TOKEN`. `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` можно заполнить позже.
4. Запустите Blueprint. Persistent Disk не нужен: прогресс хранится в Supabase.
5. После деплоя откройте `https://slave-game-1.onrender.com/api/health`. Ожидаемый ответ: `{"status":"ok","database":"postgresql"}`.
6. Отправьте боту `/start`. Кнопка «Воспитать» откроет игру.

Если изменили имя сервиса в `render.yaml`, также измените `GAME_URL` и `FRONTEND_URLS` на фактический HTTPS-адрес. Не запускайте одновременно локального бота и Render-бота с одним токеном: Telegram не допускает два polling-процесса.

Схема PostgreSQL обновляется при старте приложения, поэтому прогресс не зависит от жизненного цикла контейнера.

## ЮKassa

Кнопка **+** возле баланса открывает пакеты клятв: 100 за 99 ₽, 500 за 449 ₽, 1000 за 899 ₽ и 3000 за 2499 ₽. Оплата проходит на странице ЮKassa; игра не запрашивает почту, телефон и другие данные для чека. В Render задайте:

- `YOOKASSA_SHOP_ID` — shopId магазина;
- `YOOKASSA_SECRET_KEY` — секретный ключ API.

В кабинете ЮKassa укажите webhook:

```text
https://slave-game-1.onrender.com/api/yookassa_webhook
```

Нужно событие `payment.succeeded`; событие об отмене также обрабатывается. Приложение не доверяет содержимому webhook: оно повторно запрашивает платёж у ЮKassa, сверяет владельца и сумму и начисляет клятвы только после подтверждения. Повторная доставка webhook не дублирует начисление. Ключи используются только на backend и не попадают в браузер. После оплаты игрок возвращается на `https://slave-game.karvomilos.workers.dev`.

## API

- `POST /api/load_data` — создаёт игрока, применяет `referrer_id` при первом входе и возвращает прогресс.
- `POST /api/save_data` — сохраняет прогресс.
- `POST /api/referral` — возвращает ссылку и число приглашений.
- `GET /api/auction` — активные лоты с уровнем, склонностью, возрастом и ценой.
- `POST /api/auction/list` — атомарно выставляет текущего персонажа и освобождает место для нового.
- `POST /api/auction/buy` — атомарно переводит кристаллы продавцу, а персонажа и его рейтинговый возраст — покупателю.
- `POST /api/create_payment` — принимает только `amount` и `telegram_id`, создаёт redirect-платёж SDK ЮKassa и возвращает `confirmation_url`.
- `POST /api/yookassa_webhook` — проверенный webhook начисления по курсу 1 ₽ = 1 клятва.
- `POST /api/payments/create` и `POST /api/payments/yookassa` — совместимые адреса предыдущей версии.
- `GET /api/leaderboard` — таблицы лидеров.
- `GET /api/health` — проверка API и подключения к базе.

Запросы с игровыми данными требуют подписанный Telegram `initData`.
